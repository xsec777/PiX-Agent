# ADR 0001 — 主从会话隔离派发架构 (Planner-Worker Session Spawning)

## 状态
已采纳（2026-11-04，设计决策）

**v2.9.1 实现状态：未实现的目标架构。** 当前未实现 Planner/Worker 子会话派发、隔离与标准化结果回写；下文保留目标设计，不代表本版本功能承诺。文中场景与示例均为虚构，不代表实测。

## 背景
在红队自动化渗透测试中，资产搜集后往往产出数十至上百个待测端点（`EndpointNode`）。若在单一 Agent 会话中连续执行所有端点的探针、变异与利用，长期累积的工具输出和思维惯性将迅速引发上下文通胀与认知漂移。借鉴 Sapper-v2（腾讯攻防冠军）与 ARTEX 工业级系统的成熟经验，我们必须对全局规划大脑与局部执行手脚实施物理隔离。

## 决策
我们决定采用 **主从会话隔离派发架构（Planner-Worker Session Spawning）**：
1. **主控会话 (Planner)**：仅负责全网 4D 超图感知、端点台账维护、优先级队列推导、结案门禁裁决与报告冻结。**严禁主控会话直接调用底层渗透工具执行单点发包**。
2. **执行子会话 (Worker)**：针对特定端点或同构资产动态派发独立的 Worker 会话。Worker 仅携带局部的 `TaskEnvelope` 任务信封，自主选择工具链执行探针与阻抗变异。
3. **标准化结果回写**：Worker 执行完毕后，只将结构化流转结果（状态、原始请求包、关键差分证据）回写至 4D 超图并立即销毁自身，绝不把海量执行回显污染主控大脑。

## 后果与权衡
- **积极影响**：
  - 主控上下文终身纯净紧凑，可支持长达数天的高强度攻防战役而不出现注意力退化；
  - 天然支持“模型分层”经济学（主控使用旗舰智能模型，子执行者使用高速廉价模型）；
  - 不同端点测试完全物理隔离，某端点的超时或异常绝不毒化全局推演。
- **代价与约束**：
  - 必须建立严格的子会话派发与超时看门狗回收通道；
  - 需标准化 `TaskEnvelope` 与结果回调的数据契约。
