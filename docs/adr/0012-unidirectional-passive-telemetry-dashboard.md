# ADR 0012 — 单向只读数据流遥测大屏与终端唯一控制权原则 (Unidirectional Passive Telemetry Dashboard)

## 状态
已采纳（2026-11-04，设计决策）

**v2.9.1 实现状态：只读 HTTP 通道已实现。** `matrix-server.mjs` 提供看板页面、`/events` 与 `/api/matrix`，允许 GET/HEAD，拒绝其他方法；默认绑定 `127.0.0.1`。只读不等于免鉴权或绝对安全，仍须限制本地绑定或部署访问控制，并对输出事实、凭据与证据脱敏；当前不提供应用层鉴权。推流不保证零延迟。文中域名、报文与场景均为虚构示例，不代表真实秘密或实测。

## 背景
在确立了基于 Node.js 原生 SSE 的攻防接口实时监控大屏（Port 30142）后，面临一个关键的人机协同控制边界问题：是否应在大屏界面上增加“紧急拉黑端点”、“插队优先测试”等双向修改状态的交互按钮。备选方案包括：
1. 赋予大屏双向控制权，支持通过 HTTP POST 直接拦截端点或插队；
2. 坚持单向只读数据流，大屏纯粹作为“只读仪表盘/玻璃座舱”，所有指挥控制指令（C2）严格收敛于终端命令行对话中。

## 决策
我们决定采用 **单向只读数据流遥测大屏与终端唯一控制权原则 (Unidirectional Passive Telemetry Dashboard & Terminal Command Authority)**：
1. **大屏纯只读单向推流**：
   - 默认 30142 端口的 `matrix-server.mjs` 服务提供只读页面、`/events` (SSE) 与 `/api/matrix`，允许 GET/HEAD，拒绝其他 HTTP 方法，不提供修改状态或终止进程的 HTTP 通道；
   - 看板职责是呈现已记录的 4D 超图事实、闭环状态与证据片段，充当“可观测性驾驶舱”。文件总线约 500ms 合并更新，服务端文件监听另有 150ms 防抖，不保证零延迟或固定毫秒内送达；
2. **终端唯一控制权原则 (Terminal Command Authority)**：
   - 所有的目标授权（`/auth`）、黑名单排除、模式切换（`/mode`）以及任务干预，**一律强制收敛于主控终端会话（CLI / Chat）**；
   - 不提供网页写入通道可减少误触、并发写入和 CSRF 状态修改的攻击面，但不保证消除数据泄露、前端注入或其他服务风险；
3. **访问控制与证据保护**：
   - 只读数据仍可能包含目标信息、凭据和原始证据。服务默认绑定 `127.0.0.1`，应保持本地访问；如需远程访问，应部署鉴权与访问控制，并核验输出已脱敏。当前没有应用层鉴权，也未实现 ADR 0006 的全链路卫生闸门，不能将只读解释为免鉴权或绝对安全。

## 后果与权衡
- **积极影响**：
  - 数据读取路径为超图 ➔ 文件 ➔ SSE ➔ 浏览器，HTTP 通道不承担状态修改；
  - 减少服务端写入 API 及其权限管理复杂度；
  - 减少远程状态修改的攻击面，但外部端口暴露和敏感信息读取仍有风险，需本地绑定、访问控制与脱敏。
- **代价与约束**：
  - 人类操作员若需干预测试流程，必须在主控终端对话中发出指令，无法直接在网页上点选刹车。
