# ADR 0006 — 确定性双层证据卫生与脱敏拦截闸门 (Deterministic Dual-Layer Evidence Hygiene Gate)

## 状态
已采纳（2026-11-04，设计决策）

**v2.9.1 实现状态：未实现的目标架构。** 当前未实现本文所述覆盖请求、响应与全部入账路径的双层证据卫生闸门，也未实现物理强制 `LIMIT 3`。下文保留目标设计；实际导出、看板与证据仍需核验和脱敏，不能视为自动满足全部隐私要求。文中凭据占位符、样本与场景均为虚构，不代表真实秘密或实测。

## 背景
在黑盒渗透、红队演练与 SRC 漏洞上报中，证据（Evidence）的核心价值是让审计人员能够精准复现并信服。然而，Worker 在测试过程中捕获的原始报文往往携带攻击者自身的测试会话（Cookie、Bearer Token、内部 API 密钥）以及目标业务库的真实用户敏感隐私（PII，如手机号、身份证、密码 Hash）。若缺乏严格的物理过滤闸门，单纯依靠大模型自觉打码，实测漏网率极高，将导致活会话泄露与严重合规红线违规。

## 决策
我们决定采用 **物理流确定性双层证据脱敏拦截闸门 (Deterministic Dual-Layer Evidence Hygiene Gate)**：
1. **第一层 · 请求报文会话洗脱闸门 (Request Gate)**：
   - 在 `evidenceRequest` 录入端点台账与证据库的物理管道上，挂载确定性正则清洗器；
   - 自动将 `Cookie: ...`、`Authorization: Bearer ...`、`Token: ...`、`X-Api-Key: ...` 统一无害化替换为 `[REDACTED_COOKIE]`、`[REDACTED_TOKEN]`；
   - **复现保真原则**：严格保留请求头键名、请求行参数名、时序与 JSON 传输结构，确保审计方能够对照日志无损复现，但彻底剥离真实活凭据。
2. **第二层 · 响应报文隐私掩码与数据面最小证明闸门 (Response & PII Gate)**：
   - 自动对 `evidenceResponse` 响应体中的手机号（`1[3-9]\d{9}` ➔ `138****0000`）、身份证号、密码明文实施实心掩码覆盖；
   - **数据面实证最小化原则 (Minimum Proof Principle)**：证明数据泄露或越权危害时，物理流强制执行“总量计数 (`COUNT(*)`) + 最小真实样本 (`LIMIT 3`)”，若工具回显包含长列表数据，底层机械化自动截断至前 3 行，并附带 `... [遵循数据面最小实证原则已截断其余记录]` 声明。
3. **零模型依赖**：全量脱敏逻辑全部由底层 TypeScript 正则管道物理保证，哪怕大模型疏忽大意原样提交，也绝不允许任何敏感活凭据流向超图底表与看板前端。

## 后果与权衡
- **积极影响**：
  - 100% 物理阻断攻击者自身测试凭据的泄露风险，杜绝活会话被第三方恶意重放；
  - 严格满足企业安全合规与国家红蓝演练对数据隐私保护的刚性门禁要求；
  - 导出的事实底表（`targets.csv`、`pix-facts.md`）达到工业级交付标准，无需人工二次脱敏。
- **代价与约束**：
  - 正则清洗规则必须严谨，需避免过度误伤具有特殊格式的漏洞参数名。
