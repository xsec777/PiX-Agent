# ADR 0003 — 双档动态模型分层调度与升档机制 (Dual-Tier Model Scheduling & Escalation)

## 状态
已采纳（2026-11-04，设计决策）

**v3.7.0 实现状态：部分实现。** 现有 ModelRouter 与 SubAgentModelPreference 支持本地档位配置、显式 FastTier 偏好及查询计数；没有真实模型服务调用、宿主模型切换、自动升档或实测成本收益。下文保留目标设计，不构成运行时保证。文中场景与示例均为虚构，不代表实测。

## 背景
大模型在自主渗透测试中存在典型的“算力浪费与注意力不均”矛盾：80% 的工作属于机械性的探针发送（如对 URL 拼接测试单引号、尝试访问默认路径），若全量使用顶级旗舰模型（如 Claude 3.5 Sonnet / DeepSeek-R1），Token 消耗极大且推理时延较高；若全量使用轻量快速模型，面对复杂 WAF 变异、多阶漏洞利用与因果推理时又极易卡死在盲区。借鉴 Sapper-v2“分层用脑”以 10 亿 Token 击败 45 亿 Token 夺冠的实战经验，必须实施模型层面的经济学分层。

## 决策
我们决定采用 **双档动态模型分层调度 + 战况受挫自动升档机制 (Dual-Tier Model Scheduling & Escalation)**：
1. **双档位配置支持**：
   - **`Smart Tier`（旗舰大脑）**：默认供给 **Planner** 消费（负责全局 4D 超图拓扑分析、攻击链规划、因果推演与结案门禁判定）；
   - **`Fast Tier`（高速轻量脑）**：默认分配给普通 **Worker** 消费（负责快速并发发送基础探针、解析目录与结构化提取），追求极速与极低 Token 成本。
2. **战况受挫动态升档机制（Escalation Promotion）**：
   - 当某个由 Fast Tier 驱动的 Worker 在攻坚端点时，遭遇 WAF 阻断或连续变异失败达到阈值（`failureStreak >= 2` 或状态流转为 `bypassing` / `escalating`）时，主控判定该端点为“高抗阻硬骨头”；
   - 主控立即终止轻量尝试，重新组装携带阻抗上下文的 `TaskEnvelope`，**指派 `Smart Tier` 旗舰模型接管并启动深度变异攻坚**。
3. **缺省平滑退化**：若用户仅配置了一个模型，系统自动将 `Smart Tier` 与 `Fast Tier` 指向同一模型，平滑退化为单模型运行，配置零阻碍。

## 后果与权衡
- **积极影响**：
  - 预期可直接压缩 70% 的常规探测 Token 消耗与网络等待时延；
  - 攻坚时动态倾斜最强智力，达成“轻量测面、旗舰破点”的帕累托最优；
  - 极大提升模型调度的实战专业度与工程可解释性。
- **代价与约束**：
  - `models.json` 配置体系需支持 `smart` 与 `fast` 两组模型别名映射；
  - 主控需在内存中维护端点变异深度与模型派发绑定记录。
