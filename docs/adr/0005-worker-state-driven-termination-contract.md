# ADR 0005 — Worker 状态机驱动的四态终结契约与物理看门狗 (State-Driven Four-Outcome Termination Contract)

## 状态
已采纳（2026-11-04，设计决策）

**v2.9.1 实现状态：未实现的目标架构。** 当前未实现 `worker_submit`、Worker 四态终结契约和轮次/墙钟看门狗。现有 `update_endpoint` 的 rejected 检查主要验证 `testedTimes >= 3`，未验证测试维度覆盖，也不等同于本文契约。下文保留目标设计，不代表本版本强制执行。文中场景与示例均为虚构，不代表实测。

## 背景
在主从会话隔离架构中，执行子会话（Worker）的生命周期控制是决定整个系统稳定度与 Token 消耗的关键边界：若对子会话缺乏刚性约束，大模型极易陷入两个极端——在注定测不通的静态参数上盲目空转数十轮，烧光 Token；或者仅发了一次常规单引号未见报错就草率判定“无漏洞”提前放弃。必须通过代码级的终结工具契约与底层安全看门狗，为 Worker 划定明确的行动下限与退出上限。

## 决策
我们决定采用 **状态机驱动的四态终结契约 + 物理看门狗兜底机制 (State-Driven Four-Outcome Termination Contract)**：
1. **强制专用终结工具 (`worker_submit`)**：
   - Worker 会话中严禁通过纯文本闲聊结束任务，必须调用 `worker_submit` 工具向 Planner 交付结构化成果；
2. **四态确定性终结结局 (Four Outcome Contract)**：
   每次调用 `worker_submit` 必须且只能归入以下四种结局之一：
   - **`confirmed`（快速成功退出 · Early Exit）**：一旦探针捕获到明确漏洞差分（经 `verifier` 二次校验通过），立即携带原始请求包与差分切片交付结案，绝不多消耗任何后续推理轮次；
   - **`escalating`（纵深突破）**：发现未授权敏感数据或初始立足点，提交立足点证据，请求主控规划下一步横向/提权指令；
   - **`bypassing`（遭遇强阻抗）**：连续 2 组变异尝试均被 WAF 阻断且无法突破，Worker 达到初级能力上限，主动挂起并提交阻断特征，**触发 ADR 0003 的 SmartTier 旗舰模型升档换将**；
   - **`rejected`（充分证伪）**：**刚性门禁硬性拦截**——必须在其内部测试记录中完成常规探针、编码变异、参数形态 3 次以上有效测试无差分，才允许以 `rejected` 提交；
3. **底层物理安全看门狗兜底 (Watchdog Ceiling)**：
   - 单个 Worker 会话设置物理硬上限：推理轮次 ≤ 6 轮，墙钟耗时 ≤ 180 秒；
   - 一旦触发硬上限，底层看门狗强制中断子会话，回收上下文并向台账记录为 `blocked`，杜绝任何意外死循环。

## 后果与权衡
- **积极影响**：
  - 成功时立刻收口（Early Exit）在海量常规扫描中可节省大量无谓的 Token 开销；
  - 阻抗受挫时主动触发旗舰模型接管，与双档模型调度（ADR 0003）形成天然闭环；
  - 证伪门禁与物理看门狗彻底根治了“AI 偷懒漏报”与“AI 钻牛角尖死循环”两大致命顽疾。
- **代价与约束**：
  - Worker 的 System Prompt 必须注入四态终结契约，且缺少合法状态时调用 `worker_submit` 将被底层报错拒绝。
