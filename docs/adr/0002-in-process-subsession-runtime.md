# ADR 0002 — Pi SDK 内存级子会话隔离与通信协议 (In-Process Sub-Session Runtime)

## 状态
已采纳（2026-11-04，设计决策）

**v2.9.1 实现状态：未实现的目标架构。** 当前未实现 `spawn_worker`、独立子会话运行时、`WorkerResult` 内存交付与资源回收；下文保留目标设计，不代表本版本功能或时延保证。文中场景与示例均为虚构，不代表实测。

## 背景
在确立了主从会话隔离派发架构（ADR 0001）后，必须决定 Worker 子会话的具体派生机制与进程通信方式。主要备选方案包括：基于操作系统的无头 CLI 独立进程（类似 Sapper 借助 tmux/文件邮箱）与 Pi SDK 内存级独立会话实例。考虑到 PiX 面向的主流工作环境为 Windows（易出现多进程文件锁冲突与句柄泄漏），通信延迟与跨平台一致性是核心考量点。

## 决策
我们决定采用 **Pi SDK 原生内存级子会话隔离（In-Process Sub-Session）**：
1. **内存级隔离派生**：通过封装 Pi SDK 的独立会话上下文创建接口，主控会话通过 `spawn_worker({ taskEnvelope })` 工具在同一个宿主 Node.js 进程内动态拉起纯净的子会话实例。子会话拥有独立的对话历史与工作区，其执行过程绝不污染主会话的上下文窗口。
2. **结构化对象闭环交付**：子会话执行完毕后，直接在内存中向 Planner 交付强类型的 `WorkerResult` 对象（包含流转状态、测试动作、原始 HTTP 请求包与响应差分证据）。
3. **熔断与销毁机制**：子会话设置严格的超时看门狗与最大推理轮次（默认 ≤ 6 轮），测试完毕后立即释放子会话资源并触发垃圾回收。

## 后果与权衡
- **积极影响**：
  - 纯 TypeScript 内存级调度，彻底摆脱外部 tmux、文件邮箱等复杂中间件依赖，Windows / Linux 跨平台原生一致；
  - 零磁盘 I/O 延迟，执行结果瞬时注入，看板（`LiveMatrix`）得以毫秒级响应状态变更；
  - 避免了 Windows 环境下高频创建/销毁 Node.js 进程带来的巨大 CPU 与句柄开销。
- **代价与约束**：
  - 所有会话共享宿主进程内存，若某个 Node 原生 C 扩展发生底层 Crash，会波及主进程（因此必须通过严格的输入校验与超时防护消除此类风险）。
