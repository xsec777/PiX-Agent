# ADR 0011 — 双模混合报告流水线与数据面物理隔离 (Hybrid Reporting Pipeline & Data Plane Isolation)

## 状态
已采纳（2026-11-04，设计决策）

**v3.5.0 实现状态：部分实现。** 新增显式本地报告组装模块，读取输入台账并计算同范围统计、规则处理后的展示证据和 SHA-256 内容摘要；不补造缺失证据、不自动定级。当前没有受控 LLM 管理摘要或双面合流，也未接入旧导出入口。哈希不是签名，模板不保证输入真实，80%/20% 并非实测比例。下文保留目标设计，不构成已实现保证。

## 背景
大模型在自主生成长篇交付报告（如几千字的渗透测试报告）时，存在不可避免的随机性与幻觉风险：模型极易在文末主观编造测试中未实际触发的 CVE 漏洞、混淆不同主机的 IP 地址、或篡改原始 HTTP 请求包中的参数名，破坏技术报告的法律证据严肃性。然而，若完全采用代码静态拼接，报告又缺乏面向企业管理层的安全态势评估与定制化整改指导。正如第一性原理所指出的：**“大模型不可能存在绝对 0 幻觉，工程的本质是通过结构化物理隔离来约束并驾驭它的长处与短处。”**

## 决策
我们决定采用 **双模混合报告流水线与数据面物理隔离机制 (Hybrid Reporting Pipeline & Data Plane Isolation)**：
1. **数据面绝对物理隔离 (Data Plane Isolation · 占比 80%)**：
   - 全网端点台账清单、统计图表、已坐实漏洞列表、原始复现 HTTP 请求包 (`evidenceRequest`)、关键差分响应切片 (`evidenceResponse`) 及横向穿透拓扑图；
   - **核心刚性约束**：上述数据全部由底层 TypeScript 模板引擎从 4D 超图中以只读方式直接提取并拼装，**严禁大模型二次改写或介入数据面的文本生成，确保证据数据 100% 机械确定与不可篡改**；
2. **管理面受控单次激发 (Executive Summary Plane · 占比 20%)**：
   - 仅在收官冻结阶段，发起一次受控的轻量 LLM 会话，将已锁定的全网统计数据（漏洞总数、高危分布、受影响主机）与企业行业特征作为 Prompt 约束输入；
   - 限制模型仅负责撰写两部分高阶战略咨询内容：
     ① 《管理层执行摘要与全局态势评估》
     ② 《针对本次实测暴露面的企业战略级中长期安全加固建议》
3. **成果合流与多格式分发**：
   - 管理面生成完成后，与数据面模板无缝缝合，一键导出为标准的交付级 Markdown (`/report`) 与用于排版水合的结构化 JSON。

## 后果与权衡
- **积极影响**：
  - 彻底消除了漏洞编造、IP 混淆与请求报文被篡改的假阳性风险；
  - 兼具顶尖咨询机构的专业管理层汇报水准与不可辩驳的底层流量实证；
  - 仅在收尾时调用一次单次模型，开销极低（节约 85% 报告撰写 Token）。
- **代价与约束**：
  - 代码层需维护清晰的 Markdown 模板分段语法。
