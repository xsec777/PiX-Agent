# PiX V3 架构与实现边界说明

> 版本：v3.6.0 文档整理版。本文描述目标架构、已实现的离线原语和当前限制，不代表所有目标能力已经接入生产运行时。

## 定位

PiX V3 的目标是以结构化台账、任务信封、Worker 槽位、证据卫生和报告模板减少长会话中的认知漂移。当前公开仓库以**显式调用的本地模块**为主；真实 Pi 子会话执行器、自动模型切换、自动隧道授权、真实域控策略探测和跨进程账号锁定防护尚未完整实现。本文中的“物理”“强制”等架构措辞仅描述设计目标，不构成运行时保证。

## 已实现的本地能力

- `state.ts`：端点台账、状态记录、证据字段及本地快照持久化。状态标签由调用方提供，不等于独立确证。
- `task-envelope.ts`：不可变任务契约、Host 白名单、禁止路径和默认只读边界的本地校验。
- `worker-pool.ts`、`concurrency.ts`、`throttler.ts`：进程内槽位、规范化 Host 字符串锁和调用方反馈驱动的并发窗口状态；不自动接入真实网络响应或协调其他进程。
- `watchdog.ts`、`termination.ts`、`worker-result.ts`：轮次/时间计算、四态终结契约校验，以及要求 Worker、信封、端点与看门狗绑定的结果对账；不自动创建或取消子会话。
- `redaction.ts`、`pii-masker.ts`：在 WorkerResult 对账路径对请求凭据、有限格式 PII 和支持的响应形状进行规则处理。其他写入入口、任意格式敏感信息、历史数据和导出文件仍需人工核验。
- `ad-safety.ts`：由调用方提供域锁定策略，按进程内账号键限制本地记账。未知策略或阈值不大于 2 时拒绝记账；不探测域控、不执行认证，也不能保证真实账号不锁定。
- `tunnel-gate.ts`、`cleanup-watchdog.ts`：命令文本规则拦截、可信调用方管理的本地临时文件和子进程句柄显式清理；不等于网络隔离、远程清理或零残留保证。
- `report-engine.ts`、`executive-summary.ts`：输入范围内的证据报告组装与本地规则摘要草稿。SHA-256 是展示内容校验值，不是签名；风险保持未评估，不调用 LLM 或网络服务。
- `matrix-server.mjs`：默认绑定 `127.0.0.1` 的只读 SSE/JSON 快照服务。槽位字段来自快照或空闲占位，不接入实时 WorkerPool；无应用层鉴权，CORS 不是访问控制，输出证据需要脱敏。

## 目标架构与已知差距

| 目标 | 当前状态 |
|---|---|
| Planner 自动派发真实 Worker 子会话 | 未接入；槽位与信封是显式调用原语 |
| SmartTier / FastTier 自动模型服务切换 | 仅本地配置选择建议，不读取或修改宿主模型设置 |
| 实时 HostMutex / 自适应发包流控 | 仅同进程、调用方提供反馈的状态管理，不连接真实响应或协调多进程 |
| 全域证据卫生闸门 | 仅特定对账路径和有限规则；其他证据入口、历史数据及导出仍需核验 |
| 自动域策略探测与防锁号 | 仅调用方提供策略后的本地记账限制，不发起探测，也不拦截外部认证 |
| 任务书授权隧道与自动退出清理 | 命令规则拦截和显式本地清理；没有目标环境零残留保证 |
| 混合报告自动合流 | 报告引擎与摘要草稿独立显式调用，未接入旧导出命令 |
| 实时多 Worker 遥测 | 只读快照展示与空闲占位，未绑定实时 WorkerPool |

## 使用与验证

V3 测试使用合成夹具、本地内存对象和固定输入；不连接外部目标、不执行真实凭据测试、不启动模型服务。严格类型检查和离线验收由 GitHub Actions 执行。发布前仍须逐项核对授权范围、证据归属、敏感信息与未测维度；不能用模块测试通过率替代真实环境验证。

本说明用于文档整理与能力边界对齐，不宣称 PiX V3 已构成可自主执行完整红队流程的 GA 系统。
